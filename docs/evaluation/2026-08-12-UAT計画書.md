# UAT 計画書（Public Works Stakeholder Map）

| 項目 | 内容 |
|---|---|
| 対象 | 本番（https://pwsm.mirai-dx-platform.com）の実データ公開後バージョン |
| 作成日 | 2026-08-12 |
| 目的 | 要件定義書 §11.2「非エンジニア、現場管理者、土木技術者、IT/DX 担当による UAT 承認」と KPI（初期調査時間 30% 削減）の実証 |

## 1. 前提

- UAT は**実データ投入（Issue #32）とデータ版切替が完了した後**に実施する
- 対象データ: 代表 3 地域（東京・横浜・大阪）の公開済み候補（出典保有率 100%・TTL 内）
- 対象環境: 本番（Access 保護）または検証用 staging

## 2. 参加者と役割

| 区分 | 人数 | 役割 |
|---|---:|---|
| 現場管理者 | 3 | 施工計画・事前協議の実務者。検索フローと出力の使い勝手を評価 |
| 土木技術者 | 3 | 関係機関・管轄の正確性、見落とし低減効果を評価 |
| 営業・積算 | 2 | 入札前調査の時間短縮効果を評価 |
| IT/DX 部門 | 2 | 運用性・監査・保守性・セキュリティを評価 |
| 管理者（承認者） | 1 | UAT 結果の最終承認 |

## 3. シナリオ（詳細設計仕様書 §17.3 準拠）

| # | シナリオ | 期待結果 |
|---|---|---|
| U-01 | 国道沿いの掘削・交通規制 | 道路管理者＋警察＋自治体窓口が根拠付きで候補になる |
| U-02 | 都道府県道での占用候補調査 | 都道府県道路管理者が候補になる |
| U-03 | 一級河川付近の仮設・排水 | 河川管理者が候補になり、等級による分岐注記がある |
| U-04 | 港湾区域付近の搬入・水域使用 | 港湾管理者が候補になる |
| U-05 | 市道と県道の境界付近 | 両方の候補が表示され、片方を隠さない |
| U-06 | 管轄不明・更新日不明のケース | 「要照会」「期限超過」として識別され、非断定表示される |
| U-07 | 候補→原典確認→チェックリスト→CSV/印刷 | 免責・出典・データ版・出力日時が含まれる |
| U-08 | 誤り・不足のフィードバック | 受付番号が返り、管理者側で一覧・状態更新できる |

## 4. KPI と測定方法

| KPI | 目標 | 測定方法 |
|---|---:|---|
| 初期調査時間 | 従来比 30% 以上削減 | U-01〜U-06 を「従来手法（HP＋地図＋Excel）」と「本システム」で同一ケース実施し、所用時間を比較 |
| 候補再現率 | 90% 以上 | 専門者が作成した正解候補集合とシステム候補の一致率 |
| 重大な誤断定 | 0 件 | 候補文言・出力レビュー |
| 出典 URL 保有率 | 100% | SCR-08 品質レポート |
| システム利用意向 | 8 割以上が「業務で使いたい」 | アンケート（5 段階） |

## 5. スケジュール（目安）

| フェーズ | 期間 | 内容 |
|---|---|---|
| 準備 | 1 週間 | シナリオ・正解候補集合・測定シート作成、参加者への説明 |
| 実施 | 2 週間 | 各参加者がシナリオを実施（所要時間・気づきを記録） |
| ヒアリング | 3 日 | 不具合・改善要望の分類（必須/あったら良い/不要） |
| 結果評価 | 3 日 | KPI 集計、受入判定、ロードマップ反映 |
| 承認 | 1 日 | 管理者が UAT 承認書へ署名 |

## 6. 受入判定

- **合格**: KPI 全項目達成（候補再現率 90%・時間 30% 削減・誤断定 0・出典 100%）かつ重大不具合なし
- **条件付き合格**: 軽微な改善要望を Issue 化して次リリースへ回す
- **不合格**: 主要シナリオで誤候補・欠落が確認された場合。データ修正 → 再実施

## 7. 記録とプライバシー

- 測定シートには実案件名・個人名・社外秘情報を記入しない（既存方針を踏襲）
- 結果は `docs/evaluation/UAT結果-YYYYMMDD.md` に集約し、GitHub で管理する
- スクリーンショットは候補一覧・出力のみ（個人情報を含まない）

## 8. 結果の反映先

- 不具合・改善要望は GitHub Issue 化し、Phase 1〜3 のロードマップへ反映
- KPI 未達の場合は、データ品質・ルール・UI のいずれが原因かを切り分け、修正後に再測定する
