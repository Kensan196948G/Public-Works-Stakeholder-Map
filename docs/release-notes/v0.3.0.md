## ✨ 新機能

- 🗂️ **SCR-06 データソース管理**: 公式情報源台帳（権威性・取得方式・利用条件・最終取得・エラー）+ 手動取込フォーム。利用条件未記録ソースは ⚠️ 表示（リンク+索引限定の運用・要件 §9.3）
- 📝 **SCR-07 取込レビュー**: ステージングの確認・承認・差戻し・隔離。**無レビュー公開禁止**の状態機械（`pending→in_review→approved/rejected/quarantined`・approved は終端）を domain 層で一元管理し、UI ボタン活性と API 検証が同じ遷移表を参照
- 📊 **SCR-08 品質ダッシュボード**: 期限超過（TTL）・出典保有率・利用条件未記録・推定境界・取込状態を常時監視（KPI: 出典保有率 100%・期限超過識別率 100%）
- 📚 実データ整備の運用手順書 `docs/data-registry.md`（台帳記録項目・利用条件確認・公式優先順位・品質ゲート）

## 🔧 API 追加（非本番のみ有効）

`GET /admin/sources` / `GET・POST /admin/imports` / `POST /admin/imports/:id/review`（遷移不能時 409）/ `GET /admin/quality` — 全レビュー操作は監査ログへ記録。

## 📝 設計差分の記録（PR #29 コメント参照）

- レビュー API は設計 §6.3 の `/admin/reviews` 系を `/admin/imports/:id/review` へ統合（機能同等）
- four-eyes・公開承認時の必須入力（§9.3）は認証導入後に実装（actor 識別が前提のため）
- 台帳の登録・更新 API と監査ログの `/admin` 経路統合は実データ整備・認証導入時
